# OMNI SPACE

中文优先的本地前端原型，核心演示内容以 HTML/CSS 保存。项目、文件、版本和配置仍保存在当前浏览器；账号与登录会话由 Node 服务端保存和校验。

## 本地运行

```powershell
node server.cjs
```

打开 http://127.0.0.1:4175/。本地服务默认监听 `127.0.0.1`。首次注册的账户成为管理员；后续注册账户是成员。旧版浏览器本地账户需要重新注册，原有本地项目数据不会自动删除。

验证命令：`node auth-test.cjs` 与 `node smoke-test.cjs`。两者会使用独立临时账号库，不会改动实际账户。

账号数据已连接本机 MySQL `omni_space`，连接配置位于被 `.gitignore` 忽略的 `data/db-config.json`，示例见 `data/db-config.example.json`；生产环境建议改用 `OMNI_DB_HOST`、`OMNI_DB_PORT`、`OMNI_DB_USER`、`OMNI_DB_PASSWORD`、`OMNI_DB_NAME` 环境变量。服务启动时会自动创建 `accounts`、`sessions`、`image_usage` 表。密码在服务端以 `scrypt` 加随机盐存储，登录使用 `HttpOnly`、`SameSite=Lax` Cookie；每账户最多保留 5 个有效设备会话，修改密码会撤销旧会话。图片生成必须登录，媒体文件按账户隔离访问；默认每账户每天最多 20 次图片请求，可用 `OMNI_DAILY_IMAGE_LIMIT` 调整。浏览器不会持有图片供应商的 API Key。

公开部署前使用 HTTPS 反向代理，并配置 `OMNI_HOST`、`OMNI_HTTPS=1`、`OMNI_ADMIN_EMAIL`、`OMNI_ADMIN_PASSWORD`（至少 12 位）。首次启动会创建管理员；公开绑定且未启用安全 Cookie 时服务拒绝启动。`OMNI_DATA_DIR` 可指定持久化目录，`OMNI_PORT` 可修改端口。反向代理应设置上传大小、请求超时和访问日志。

## 已跑通的本地流程

- HTML 演示场景编辑、场景时间线拖拽排序、过渡和停留时长、四类数据绑定、草稿恢复、撤销/重做、播放、打印和独立 HTML 导出。
- 导出前会检查场景根节点、数据占位符和演示配置；不完整内容会明确提示具体场景。
- 图片通过 `gpt-image-2` 生成并保存到 `generated-media/`，结果会进入图片工作区及项目画布；资产节点支持拖动和返回对应工作区。
- 视频草稿会生成本地动效预览并连接到画布。也可导入不超过 100 MB 的 MP4、WebM 或 Ogg 文件，在画布播放；切换工作区时自动暂停，刷新后从 IndexedDB 恢复。
- Build 沙箱预览及脚本错误显示。
- 项目只读规则审查、Agent 配置草稿、版本比较与恢复、文本文件管理。
- 中英文切换及移动端工作区布局。
- 服务端账户流程：注册、登录、会话恢复、退出、个人资料修改，以及管理员对成员的角色管理和移除。登录与注册有基础限流，成员操作由服务端校验，本服务最多保存 100 个账户。

## 正式上线前仍需接入

- 项目数据仍在浏览器 localStorage；需要服务端项目持久化、账户与项目归属、备份与多人协作。
- 当前账号库已使用 MySQL；多实例部署仍需共享媒体存储、集中限流、数据库备份和迁移工具，并仍需邮箱验证、找回密码和完善审计。
- 生产级账号、密钥管理、请求审计、计费控制与任务队列。当前本地图片代理固定使用 `gpt-image-2` 和 `https://api.tu-zi.com/coding`，读取本机环境凭据。
- 实际 3D 编辑引擎、AI Agent 执行、视频生成和真实项目审查服务。
- 原生 PPTX 导出、可靠的服务端 PDF 渲染、部署流水线和生产监控。

当前可发布为受控体验预览，不应标称完整生产平台。生产公开注册前还需完成邮箱与滥用防护、项目数据隔离及安全审查。

项目 `.omni.json` 备份包含视频资产元数据，不包含 IndexedDB 中的视频二进制文件；跨浏览器恢复后需要重新导入视频。动效预览不是视频文件，真实视频生成服务尚未接入。
